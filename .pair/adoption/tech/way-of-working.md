# Way of Working

Type A — Pet / PoC. Single contributor (Gianluca Carucci). See [`../decision-log/2026-05-02-project-categorization.md`](../decision-log/2026-05-02-project-categorization.md).

## Methodology

Kanban — continuous flow, no fixed sprints.

- Iteration: continuous; story enters work when blockers clear
- Cadence: weekly issue triage · monthly minor release · quarterly major (post-v1)
- No standups / planning / review (single-dev)
- Retrospective: ad-hoc per milestone (M1–M6)

## Hierarchy

**Initiative → Epic → User Story** (tasks inline in story body, no separate issues).

- Initiatives — issues labeled `initiative`
- Epics — issues labeled `epic`, `Parent issue` = initiative
- User Stories — issues labeled `user story`, `Parent issue` = epic; story points (XS/S/M/L/XL = 1/2/3/5/8) inlined in body
- Tasks — checklist in story body, generated by `/pair-process-plan-tasks`

## Naming & References

- Issue/PR titles carry only the human-readable subject — **no code prefix** (`[US-NNN]`, `[EP]`, `[INIT]` are forbidden in titles).
- The canonical issue identifier is the GitHub-assigned number (`#42`); reference issues by number in bodies, PRs, branches, commits.
- Type is conveyed by labels (`initiative`, `epic`, `user story`), not by title prefixes.
- Branch slug includes the issue number: `feat/<number>-<slug>` (e.g., `feat/31-bootstrap-monorepo-skeleton`).
- Commit messages reference the issue by number where useful: `feat(infra): bootstrap monorepo skeleton (#31)`.

## Per-Story Workflow

1. Create issue with descriptive title (no code prefix); labels `user story` + `area:*`; set `Parent issue` (epic) + `Priority` (P0/P1/P2)
2. `/pair-process-refine-story` → Todo → Refined
3. Branch `feat/<number>-<slug>`
4. `/pair-process-plan-tasks` → tasks in story body
5. `/pair-process-implement` (TDD: RED → GREEN → REFACTOR) → Refined → In Progress
6. PR title `<type>: <desc>` (no code prefix) with `Closes #<number>` in body
7. CI quality gate green
8. Self-review (single-contributor)
9. Squash merge → branch deleted → issue closed → In Progress → Done

Initiatives & epics: simpler flow Todo → In Progress → Done as children progress.

## Branching

- GitHub Flow (trunk-based)
- Default: `main` (always deployable)
- Feature: `feat/<number>-<slug>`; Hotfix: `fix/<number>-<slug>`; Tooling: `chore/<slug>`
- Short-lived; deleted post-merge
- No `develop`

## Commits

- Conventional Commits enforced via commitlint (Husky `commit-msg`)
- Types: `feat`, `fix`, `docs`, `chore`, `refactor`, `test`, `build`, `ci`, `perf`, `style`
- Scope: aligned to area labels — `cli`, `dataset`, `website`, `plugin`, `docs`, `infra`
- Style: terse (CLAUDE.md)
- Issue reference inline in subject when useful: `feat(infra): bootstrap monorepo skeleton (#31)`

## Pull Requests

- Title: `<conventional-commit message>` — no code prefix
- Body: `Closes #<number>` + summary + test plan
- Required check: CI green
- Reviewers non-blocking (single-contributor)
- Template: `.github/pull_request_template.md`
- Self-review per code-review checklist before merge

## Merge Strategy

- Method: `squash`
- Commit format: see [commit template](../../knowledge/guidelines/collaboration/templates/commit-template.md)
- Branch deleted post-merge
- Confirmation: `prompt` (`/pair-process-review` asks; switch to `silent` via decision)

## Release

- Changesets (`@changesets/cli`)
- Flow: `pnpm changeset` → version on merge → tag → `release.yml` (npm publish + website deploy + release notes)
- SemVer; on-demand cadence
- Hotfix: branch off main → fix → fast-track tag

## Definition of Done

- [ ] AC pass
- [ ] Tests green (TDD)
- [ ] `pnpm quality-gate` green local + CI
- [ ] Docs updated (`SKILL.md`, adoption files if architectural, `CHANGELOG`)
- [ ] PR squashed to main, branch deleted
- [ ] Story → Done on board
- [ ] User-facing: skill exercised once in real vault

## Testing

- Vitest unit + integration (co-located `*.test.ts`)
- TDD per CLAUDE.md (failing test first, then fix)
- CLI: temp-dir fixtures
- Skill: golden-file where deterministic
- Manual smoke per release before tag
